# WeekStreak

**Неделя — это не список дел. Это серия побед.**

WeekStreak превращает рутину в игру: вы не просто вычёркиваете задачи, а держите стрик — непрерывную серию выполненных дней. Каждая неделя становится челленджем, который хочется пройти до конца.

Собирайте задачи из разных сфер жизни, раскладывайте их по дням и смотрите, как растёт ваша линия успеха.

## Что умеет WeekStreak

### 📅 Недельная сетка

Все задачи — перед глазами: Пн–Вс, как на ладони. Ппростое переключение между неделями.

### 📂 Несколько списков — один фокус

Заведите отдельные списки под работу, спорт, учёбу и быт. Подключайте и отключайте их одной кнопкой — на сетке остаётся только то, что важно сейчас.

### ✅ Отметки по дням

Каждый день живёт своей жизнью: «сделано» хранится отдельно для каждого дня недели. Пропустили вторник — не беда, стрик считается честно.

### 🎨 Цвета источников

Каждая категория подсвечивается своим цветом. Один взгляд на неделю — и понятно, куда уходит время, а где вы системно проваливаетесь.

### 🔗 Шеринг списков

Делитесь списками по ссылке с кем угодно. Подписывайтесь на чужие списки в режиме чтения — вдохновляйтесь чужими стриками или тренируйте команду.

### 👤 Аккаунты без лишнего

Регистрация по почте и паролю — быстро, без подтверждений и ожиданий. Без входа приложение встречает формой логина и не пускает дальше.

### 📊 Статистика недели

Прогресс за выбранную неделю — в цифрах и процентах. Видно, где вы выкладываетесь, а где стоит подтянуть темп.

### 💾 Бэкап в один файл

Экспорт и импорт списков, отметок и цветов в один клик. Ваши данные — ваши правила: сохраняйте, переносите, восстанавливайте.

## Стек WeekStreak

Никаких тяжёлых фреймворков и лишних зависимостей.

### ⚙️ Backend — Node.js + Express

Лёгкий сервер, который не тормозит и не переусложняет. REST API — понятный, предсказуемый, без магии.

### 🗄 База данных — SQLite (better-sqlite3)

Вся ваша неделя — в одном файле. Синхронный, быстрый, без отдельного сервера и настройки. Идеально для личного трекера: данные под рукой, бэкап — это просто копия файла.

### ⚡ Frontend — Vue 3 (Composition API, `<script setup>`)

Реактивный. Логика живёт рядом с разметкой, компоненты — маленькие и честные. `<script setup>` убирает лишний шум и оставляет только суть.

### 🚀 Сборка — Vite

Мгновенный старт, горячая перезагрузка, продакшн-сборка за секунды.

### 🎨 Стили — чистый CSS

Без Tailwind, без Bootstrap, без UI-китов. Только свои классы и полный контроль над каждой тенью и отступом. Легко, быстро, предсказуемо.

## Запуск WeekStreak

### 🧪 Разработка

Поднимаем backend и Vite dev-сервер разом — фронтенд проксирует `/api` на бэкенд, так что CORS не мешает жить.

```bash
npm install
npm run dev
```

Затем откройте `http://localhost:5173`.

### 📦 Продакшен

Собираем фронтенд и запускаем единый сервер, который отдаёт и статику, и API из одного места. Один процесс, один порт, ноль лишних движений.

```bash
npm run build
npm start
```

Сервер по умолчанию поднимается на `http://localhost:3000`.

### ⚙️ Переменные окружения

| Переменная | Что делает |
|---|---|
| `PORT` | Меняет порт сервера (по умолчанию 3000) |
| `WEEKSTREAK_DB` | Путь к файлу БД — удобно для тестов и отдельных окружений |

## 🐳 Docker

Один образ, одна команда, ноль забот о том, что «на сервере другая версия Node». Всё собрано заранее, всё работает одинаково везде.

### 📦 Сборка и запуск одной командой

```bash
docker compose up -d --build
```

Откройте `http://localhost:3000`.

### 💾 Данные не теряются

База живёт в Docker-томе `weekstreak-data`. Пересоздали контейнер, обновили образ, перезагрузили сервер — списки, отметки и цвета на месте.

### 🔧 Без compose

Если хочется вручную — те же два шага:

```bash
docker build -t weekstreak .
docker run -d --name weekstreak -p 3000:3000 -v weekstreak-data:/app/data weekstreak
```

Собрали образ, запустили контейнер, примонтировали том — всё как в compose, только явно.

## Как это работает

Сервер отдаёт REST API (`/api/*`) и хранит данные в SQLite-базе `data/weekstreak.db` (каталог `data/` добавлен в `.gitignore`).

Доступ к данным идёт через единый слой абстракции — `server/store.js` (async-интерфейс: `store.*`, без SQL в роутах). Роуты (`server/index.js`) используют только этот интерфейс, что позволяет заменить SQLite на другую СУБД, переписав одну реализацию стора.

### Ключевые сущности

- `lists` — списки задач (`id`, `owner`, `name`); имена файлов больше не используются
- `tasks` — задачи внутри списка отдельными строками (`list_id`, `text`, время, порядок), привязка к дням недели в `task_days`
- `list_colors` — цвета списков (по `list_id`)
- `user_task_state` — отметки «сделано» по дням (`день → задача`)
- `list_shares` — токены публичных копий для шаринга (по `list_id`)
- `default_lists` — JSON-файл `server/seed/default-lists.json` с начальными задачами (источник для сида первых списков пользователя)
- `users`, `user_sessions` — учётные записи (пользователи связываются по числовому `id`), сессии и флаг `seeded` (получены ли начальные списки)

При сохранении списка задачи с уже известными идентификаторами обновляются на месте, поэтому галочки за ними сохраняются.

### 👤 Пользователи

Личное — только для своих. Публичное — по ссылке.

WeekStreak не пускает внутрь без входа: ваши списки, задачи и галочки видит только тот, кому вы сами дали доступ.

#### 🔐 Регистрация и вход

Почта и пароль — и всё. Подтверждение почты не требуется, никаких танцев с письмами. Пароль хранится в виде scrypt-хеша, что достаточно безопасно.

Вход обязателен: список задач и отметки видны и редактируются только после авторизации.

- без входа списки и задачи не показываются
- вход и выход переключают аккаунт; при выходе страница возвращается к форме логина
- личные эндпоинты API отдают `401`, если пользователь не вошёл

#### 🔗 Публичные копии

Шаринг работает без авторизации — по токену:

```text
GET /api/shares/:token
```

Получатель открывает ссылку и видит список в режиме чтения. Без токена — ничего.

#### 👀 Отметки владельца

Хотите показать чужой прогресс по общему списку? Отметки владельца доступны через:

```text
GET /api/users/:id/state
```

Так подписчик видит не только задачи, но и то, как владелец держит стрик.

Ваши данные — под замком. Ваш стрик — на виду, если вы сами этого захотите.

## 🔌 API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/me` | Текущий пользователь (`id` и `email`) |
| POST | `/api/register` | Регистрация по почте и паролю |
| POST | `/api/login` | Вход по почте и паролю |
| POST | `/api/logout` | Выход |
| GET | `/api/lists` | Список списков текущего пользователя (+ токены шерингов) |
| GET/POST | `/api/lists` / `/api/lists/:id` | Чтение/создание списка |
| PUT/DELETE | `/api/lists/:id` | Изменение/удаление списка |
| PUT | `/api/lists/:id/color` | Задать цвет списка |
| GET/PUT | `/api/state` | Получить/заменить все отметки по дням |
| POST | `/api/state/toggle` | Переключить одну отметку |
| POST/DELETE | `/api/shares` / `/api/shares/:id` | Создать/отозвать токен шеринга |
| GET | `/api/shares/:token` | Публичная копия списка по токену |
| GET | `/api/users/:id/state` | Отметки пользователя (для общих списков) |
| GET/POST | `/api/backup` / `/api/restore` | Бэкап и восстановление |

## 🧪 Тесты

Набор интеграционных тестов на встроенном раннере Node.js (`node:test`, без дополнительных зависимостей). Тесты поднимают сервер на случайном порту с временной БД в `os.tmpdir()` и гоняют его по HTTP:

### Что проверяется

- работа с аккаунтами (аноним, регистрация, логин, логаут, изоляция пользователей)
- списки по умолчанию и CRUD списков с сохранением id задач
- семантика дней недели (`days: null` — каждый день)
- отметки «сделано», цвета, шаринг, публичное состояние владельца
- бэкап/восстановление (v2 с маппингом id и v1-совместимость)

Запуск:

```bash
npm test
```

Тесты используют собственную БД (`WEEKSTREAK_DB`), прод-данные в `data/` не затрагиваются.
