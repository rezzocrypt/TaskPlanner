# Недельный план (TaskPlanner)

Чек-лист задач на неделю: соберите задачи из нескольких списков, отмечайте выполненное по дням недели и следите за прогрессом.

## Возможности

- **Недельная сетка** — задачи раскладываются по дням недели (Пн–Вс) с возможностью перемещаться по неделям
- **Несколько списков задач** — создавайте, редактируйте и удаляйте списки; подключайте и отключайте их одной кнопкой
- **Отметки по дням** — состояние «сделано» хранится отдельно на каждый день
- **Цвета источников** — наглядная подсветка, к какой категории относится задача
- **Шеринг списков** — публикуйте список по ссылке-токену и подписывайтесь на чужие списки (только для чтения)
- **Аккаунты** — регистрация/вход по почте и паролю (без подтверждения); без входа приложение показывает форму логина
- **Статистика** — прогресс выполнения задач за выбранную неделю
- **Бэкап и восстановление** — экспорт/импорт списков, отметок и цветов в один JSON-файл

## Стек

- **Backend:** Node.js, Express, SQLite (better-sqlite3), REST API
- **Frontend:** Vue 3 (Composition API, `<script setup>`), Vite
- Чистый CSS без сторонних библиотек

## Запуск

Разработка (backend + Vite dev-сервер с проксированием `/api`):

```bash
npm install
npm run dev
```

Затем откройте `http://localhost:5173`.

Продакшен (сборка фронтенда + единый сервер, отдающий и статику, и API):

```bash
npm run build
npm start
```

Сервер по умолчанию поднимается на `http://localhost:3000` (порт задаётся переменной окружения `PORT`). Путь к файлу БД можно переопределить через `WEEKPLAN_DB` — это используют тесты.

## Как это работает

Сервер отдаёт REST API (`/api/*`) и хранит данные в SQLite-базе `data/weekplan.db` (каталог `data/` добавлен в `.gitignore`).

Ключевые сущности:

- `lists` — списки задач (`id`, `owner`, `name`); имена файлов больше не используются
- `tasks` — задачи внутри списка отдельными строками (`list_id`, `text`, время, порядок), привязка к дням недели в `task_days`
- `list_colors` — цвета списков (по `list_id`)
- `user_task_state` — отметки «сделано» по дням (`день → задача`)
- `list_shares` — токены публичных копий для шаринга (по `list_id`)
- `default_lists` — JSON-файл `server/seed/default-lists.json` с начальными задачами (источник для сида первых списков пользователя)
- `users`, `user_sessions` — учётные записи (пользователи связываются по числовому `id`), сессии и флаг `seeded` (получены ли начальные списки)

При сохранении списка задачи с уже известными идентификаторами обновляются на месте, поэтому галочки за ними сохраняются.

### Пользователи

Регистрация по почте и паролю (подтверждение почты не требуется, пароль хранится в виде scrypt-хеша). Вход обязателен: список задач и отметки видны и редактируются только после авторизации. Если пользователь не вошёл, приложение показывает форму логина, а личные эндпоинты API отдают `401`.

- без входа списки и задачи не показываются
- вход и выход переключают аккаунт; при выходе страница возвращается к форме логина

Публичные копии для шаринга читаются без авторизации по токену (`GET /api/shares/:token`), отметки владельца для общих списков — через `GET /api/users/:id/state`.

## API

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/me` | Текущий пользователь (`id` и `email`) |
| POST | `/api/register` | Регистрация по почте и паролю |
| POST | `/api/login` | Вход по почте и паролю |
| POST | `/api/logout` | Выход |
| GET | `/api/lists` | Список списков текущего пользователя (+ токены шерингов) |
| GET/POST | `/api/lists` / `/api/lists/:id` | Чтение/создание списка |
| PUT/DELETE | `/api/lists/:id` | Изменение/удаление списка |
| PUT | `/api/lists/:id/color` | Задать цвет списка |
| GET/PUT | `/api/state` | Получить/заменить все отметки по дням |
| POST | `/api/state/toggle` | Переключить одну отметку |
| POST/DELETE | `/api/shares` / `/api/shares/:id` | Создать/отозвать токен шеринга |
| GET | `/api/shares/:token` | Публичная копия списка по токену |
| GET | `/api/users/:id/state` | Отметки пользователя (для общих списков) |
| GET/POST | `/api/backup` / `/api/restore` | Бэкап и восстановление |

## Тесты

Набор интеграционных тестов на встроенном раннере Node.js (`node:test`, без дополнительных зависимостей). Тесты поднимают сервер на случайном порту с временной БД в `os.tmpdir()` и гоняют его по HTTP:

- работа с аккаунтами (аноним, регистрация, логин, логаут, изоляция пользователей)
- списки по умолчанию и CRUD списков с сохранением id задач
- семантика дней недели (`days: null` — каждый день)
- отметки «сделано», цвета, шаринг, публичное состояние владельца
- бэкап/восстановление (v2 с маппингом id и v1-совместимость)

Запуск:

```bash
npm test
```

Тесты используют собственную БД (`WEEKPLAN_DB`), прод-данные в `data/` не затрагиваются.
